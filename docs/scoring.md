# 视频评分 v1

热度公式版本 `heat-v1`，原始指标和 snapshot_at 随评分流程保存。播放、互动量必须为非负整数，发布时间与快照时间有效。热度由应用计算，模型没有 heat 返回字段。

设 V 为播放量，H=max((采集时间−发布时间)/3600,1)。三项归一化均限制到 0–100：

- 播放规模 = min(100, log10(V+1)/6×100)。
- 每小时播放 = min(100, log10(V/H+1)/4×100)。
- 互动 = min(100, (点赞+2×投币+2×收藏+3×分享+评论数)/max(V,1)/0.2×100)。

热度 = 0.5×播放规模 + 0.3×每小时播放 + 0.2×互动。固定向量：100 万播放、发布/采集时间相同、20 万点赞、其余互动为 0 → 贡献 50/30/20，热度 100；全部指标为 0 → 热度 0。这是可解释的工程指标，未经全站数据校准，不代表 B 站官方热榜。

推荐度与抽象/搞笑程度由模型依据完整分 P 范围的字幕/转写/抽样画面与评论样本判断，要求 0–100 有限数字、理由和绑定来源。抽象度越高越好笑，分数越高。热门评论有采样偏差，少于 3 条、来源不足、无效引用或模型失败则不发布；不是把缺失项算作零后继续推荐。

三项算术平均，不提前舍入。严格 >60 生成邀请并由应用真实 @ 配置 UID；严格 >90 依次确认点赞、生成并发布鼓励、生成并发布邀请。等于 60 不邀请，等于 90 只邀请。前一步失败、不确定或待处理，后一步不生成也不派发。

达到阈值的工作流固定保存原始证据、评分/热度贡献、模型与提示/策略版本及邀请配置，恢复优先复用该计划与持久动作，避免评分漂移导致重发。低于阈值不创建发布流程，后续可随新快照重新分析。模型分析不使用通用缓存；字幕缓存与动态指标仍分开。
