# 实现架构

当前阶段：可靠性核心、真实 HTTP 平台基础、可恢复采集、字幕/可选转写证据与 AI 业务闭环；运行器与部署仍待实现。

采用 Python 3.11+ 异步服务，Pydantic 领域契约、aiosqlite 状态库、替换式平台/AI/证据接口。平台事实与模型输出分开：模型只能给出经校验的文本、安全结论及评分，不能决定 UID、楼层或副作用。

## 数据流与状态

采集批次和游标在同一事务保存到 inbox。处理前原子认领事件；重启恢复 processing 事件。发布 outbox 使用稳定事件/视频键，每个动作保存独立状态和前置依赖。

`pending → in_flight → succeeded / failed / uncertain / simulated`；`pending → blocked`。

先保存 in_flight，再请求平台；网络期间不持有数据库写事务。进程中断留下的 in_flight 在启动时转为 uncertain。已成功的步骤不重复执行；依赖步骤 uncertain 时，后续步骤停止。恢复读取已持久化的动作类型：评论/私信需要核实真实数字回执；点赞没有资源回执 ID，需要人工核查绑定账号 UID、目标 aid 与已点赞状态，并保存审计说明，remote_id 保持 NULL。后者证明目标状态已满足，不证明原 POST 一定成功。所有恢复只允许 uncertain 状态，检查、状态变更、额度与审计在同一事务完成。核查不到结果时继续暂停，不自动重发。平台没有事务幂等键，因此不宣称 exactly-once。

默认 `dry_run=true`、`publish_enabled=false`。任一开关关闭真实发布时，使用 `sim` 命名空间；正式发布使用 `live`。事件、游标、额度、动作和缓存均隔离。模拟成功不代表真实发送，也不调用平台写入接口。

命名空间在创建 Store 时固定。运行期间切换开关不能把已有 live dispatcher 变成模拟 dispatcher，也不能把 sim dispatcher 变成真实 dispatcher。执行入口、关注查询返回后和原子认领后均检查当前配置：认领前关闭发布时保留 pending，可恢复原配置后继续；认领后且尚未调用平台时关闭发布，标记为明确未发送的 failed 并释放额度。该 failed 动作不会自动重发，需核对审计记录后人工重新发起。已经发出的网络请求不能撤回，仍按回执成功或结果 uncertain 保存。

## 额度

按 `(UID, dm/comment)` 分开计算，默认各 5 条。窗口为 `(发送时刻−3600秒, 发送时刻]`，恰好一小时前的已发送记录不再计数。在 SQLite `BEGIN IMMEDIATE` 中一起检查动作状态、依赖、额度并完成预占和认领，UID 与渠道来自已持久化的动作。依赖未成功、动作已被处理或额度耗尽时不新建预占。独立连接并发不能超额，同一动作最多由一个执行者认领；失去争抢者返回数据库中的真实状态。

成功以发送完成时间记入窗口；在途预占和结果不确定的请求仍占位，不按预占时间自动到期。`cancel_pending` 只能原子取消尚未认领的 pending 动作，并释放其遗留预占；不能取消或释放 in_flight、uncertain、succeeded。原有独立预占/释放 API 已移除。只有明确未发送的失败路径可释放已认领额度；远端回执可以把 uncertain 确认为成功。晚到的关注或安全结论只能阻止 pending，不能覆盖另一执行者已认领或已完成的状态。模型生成失败发生在预占之前，不消耗回复额度。

拒绝回复计入同一额度，超额静默。白名单只豁免额度，仍须对方关注 bot（私信）、输入过滤和输出检查。关键词主动评论不占用召唤者额度，但仍须动作去重和全局限频。

## 运行假设与后续阶段

同一账号/数据库仅运行一个服务实例；数据库事务可抵抗并发连接争抢额度，但启动恢复不能与另一个实例的在途请求同时进行。`InstanceLock` 对规范化数据目录的持久锁文件使用内核 flock 非阻塞排他锁；login、refresh-auth、auth-status 在打开凭据或数据库之前取得锁，并持有至命令结束。等价路径和目录符号链接不能绕过互斥，不同目录独立。退出、异常、取消或进程死亡释放内核锁，始终保留文件 inode，不用 PID 文件判断存活。后续运行器复用同一入口。仅支持 macOS/Linux 本地文件系统，不提供跨主机分布式锁。数据目录不进入 Git，凭据原子保存并限制文件权限。

平台基础已提供固定 HTTPS 主机、超时/响应体/并发限制、无底层写重试的 HTTP 适配器。读取也不自动重试；后续运行器负责有限退避。业务错误、协议异常、限频、验证码与登录失效保持区别。平台响应正文和凭据不用于错误信息或日志。

扫码通过 nav 核实身份后保存凭据；状态库新增版本 2 的全局 account_uid 绑定，sim/live 共享这一账号约束，不自动清库换账号。平台操作与登录续期使用同一锁，Cookie/CSRF 始终取同一代凭据。续期状态为 `stable → refresh_started → confirm_pending → confirm_started → stable`。换新前持久化意图；新凭据与旧 token 原子保存后再确认。只有 confirm_pending（尚未发出确认）可在重启后继续；refresh_started/confirm_started 均可能已经发出 POST，缺少幂等依据，停止自动请求并要求重新扫码。该窗口不宣称无损自动恢复。

发布适配器在内部限频等待后再次检查总开关与门禁。明确平台拒绝可释放额度；未知业务码、超时、断连、HTTP 异常和缺失消息/评论回执保持 uncertain。点赞 code=0 表达平台已接受 `like=1`，没有虚构远端资源 ID。真实 @ 由配置 UID 与平台名称重新核验后构造，最终长度和私信 UTF-8 字节数也检查。

AI 与业务服务已接通单轮处理和有预算的转写。后续完成运行器、指标、脱敏日志、Docker、故障恢复 CLI 和完整端到端验收。

## 可恢复采集

@ 通知由已验证账号的认证 feed 获取；只接受视频评论，使用 subject_id/source_id/root_id 定位，不解析正文链接。显式 at_details 存在时核对目标 UID。事件键为评论 aid/rpid，顶层通知的 root=source_id，子楼层保留原 root；不完整定位直接停止该页。采集不设置安全批准，也不触发发布。

每个倒序扫描保存已完成 watermark、本次固定 head 和下一页续点。达到页数预算仅保存续点；读到旧水位或明确末页才能把 watermark 推至 head。新消息不改变正在完成的旧扫描，完成后下一次从最新页补入。首次历史范围默认一小时，HTTP 前持久化，不随失败重试的时间后移。

私信会话发现使用微秒时间戳，消息使用每用户独立序号与秒级发送时间；读取消息页，last_msg 仅用于发现任务目标。版本 3 新增 collection_jobs，发现页进度与 UID/目标序号在同一事务落库。各私信任务每轮最多处理一页，并用数据库序号轮转，时钟不前进也不会固定优先同一个用户。发现页与消息页分别有 max_pages 预算，避免发现积压占完消息预算。发现失败和单个异常消息页仍允许其他持久任务处理；错误继续上报，异常任务保留进度并记录错误类型，不记录原文。自己发送、撤回、非文本/非一对一、初始历史范围外消息有汇总忽略审计。

会话时间边界使用重叠查询；相同时间的大页若无法前进，报错保留水位和任务。该接口没有已核对的 UID 二级分页键，不能保证任意密集时间碰撞都能自动排空。所有畸形页、非倒序页、空但仍有更多的页、重复/不前进游标都不推进；SQLite 事务内没有网络等待。

## 视频事实与字幕证据

搜索分页按 aid 去重并保留匹配关键词，数量有配置预算；高亮 HTML 仅转为文本。视频详情验证 aid/BVID、顺序分 P/CID、发布时间和各项指标。热门评论样本携带采集时间、排序、实际数量、平台报告总数与截断状态，不代表全体舆情。

全视频逐 P 查询轨道，按语言优先级下载并校验结构/时间。明确无轨道且已启用转写时，核对音频目标、下载 AAC/M4A 并交给独立转写接口。字幕与音频共享整部时长/分 P/字节/文本预算，转写另有上传/调用/响应限制。所有所需 P 完成才 complete=true，不表达视觉理解；部分或超限返回证据不足，临时服务失败进入持久退避。每 P 保存类型、语言、模型、获取时间和来源，不保存媒体或签名 URL。

独立下载器仅允许已核对的字幕和音频确切 HTTPS 主机，拒绝伪域名、IP、用户信息、异常端口及重定向。空 Cookie/Authorization 防止附带凭据；总超时与实际流式字节预算生效，签名 URL 不持久化或写普通日志。音频直接上传，无本地解码或 shell；客户端无隐式重试。详见 [transcription.md](transcription.md)。

内容缓存键包含格式版本、aid、完整 CID 范围、语言优先级、文本/时长预算及转写开关/模型；读取时重新校验结构、范围、来源与预算，损坏或过期重新抓取。并发调用共享内容任务，单个调用取消不破坏其他调用；失败移除任务，服务关闭取消遗留任务。缓存只保存文本与来源，动态播放指标和评论另行获取并携带时间。评分没有通用模型缓存；达标工作流保存不可变的证据、评分与版本快照，供中断后继续。

## AI 与业务事务

AIClient 将版本化系统规则与 JSON 数据分开，有限并发、总超时、输入/输出预算和调用限频；严格验证单条 assistant 结构化结果。六种文本生成共享人格，输入、来源与输出分别检查；应用决定目标、引用与副作用，模型没有平台工具。完整契约与范围见 [ai-policy.md](ai-policy.md)。

BusinessService 原子认领事件，读取数据库原始 payload；事件完成与已批准动作写入同一事务，再交给 Dispatcher。额度初查只节省模型请求，最终预占仍由发布事务负责。拒绝、总结与陪伴共用回复动作和限额；未知安全结论、模型/平台错误保留任务，work_retries 记录持久指数退避。

关键词候选通过来源检查和评分后保存不可变工作流，包含 aid、完整证据、客观热度分解、模型评分、邀请 UID 与提示/策略版本。稳定动作键保证重启不重复生成已保存文本；每一步完成后才生成后续文本。版本或邀请配置不匹配时暂停该工作流。评分公式与边界见 [scoring.md](scoring.md)。

## 生命周期与调度

运行器先锁目录，再验证模型配置、打开资源并核实账号/恢复确定的续期阶段，最后调用一次 recover。采集、搜索、事件、动作、发现、续期分别拥有一个调度循环，单调时钟控制等待；SQLite 到期重试用墙钟。业务处理批次和并发均受限，禁止无界任务。平台认证错误使用进程内 sticky 通知，不携带请求/凭据；转换为关注未知或发布结果后，通知仍能停止新请求。

退出先停止新工作、等待有限在途任务，再取消；Dispatcher 将被取消的在途发布保存为 uncertain。共享证据任务、HTTP、数据库、目录锁依次关闭。不能通过修改 publishing/namespace 暂停认证故障；下次 login 在服务退出后取得同一锁。

schema 5 增加 discovery_jobs 到期候选与 workflow_states；迁移保留旧流程。候选低分/证据不足延后一个 discovery.interval，成功推荐终身去重。未完成流程独立于后续搜索；依赖 uncertain/failed/blocked 时暂停，人工核实为成功后可枚举继续。可发布动作枚举排除未成功依赖，避免前列积压饿死其他动作。
